# 演示语料检索评估报告（2026-08-05）

语料：`linkedin_ml_cnuk_demo_v1`（31,879 岗 / 120,584 块，线上正在服务的语料）
脚本：`scripts/evaluate_demo_corpus.py --include-raptor`
产物：`data/eval/demo_corpus_v1/{labels.jsonl, rankings.json, manifest.json}`

## 为什么要重做标注

原评估集（Kaggle arshkon 1000 岗 + 15 条查询的人工标注）与演示语料源自**不同数据集**：
117 个人工标注的相关岗位在演示语料中命中 0 个，旧标签完全不可复用。因此本轮在
"系统实际服务的语料"上重建标注与指标；原人工标注数字仍然有效，但只描述原评估语料，
两组数字**不可横向比较**（论文中须分开呈现）。

## 方法（评测依据）

1. **查询**：复用原 15 条纯语义查询（不带地点/签证约束，来自 `data/eval/resume_queries.jsonl`）。
2. **池化（TREC pooling）**：每条查询取 hybrid(top 30) 与 hybrid+RAPTOR(top 30) 的
   候选并集为标注池（实测每池 38–48 岗）；单通道基线（bm25 / dense）在同一池内按
   各自分数重排。
3. **标注**：池内每个 (查询, 岗位) 对由 DeepSeek fast（JSON 模式、严格判据：职业方向
   与技能要求实质匹配，忽略合成公司/城市名）判定二值相关性，共 652 对。
4. **指标**：`app/evaluation/metrics.py` 的 Precision@K / Recall@K / MRR / NDCG@K。

## 读数

- **混合检索显著优于 BM25 单通道**（P@5 0.72 vs 0.44；NDCG@5 0.727 vs 0.476）：
  查询是自然语言技能描述、JD 是英文原文，词面匹配天然吃亏，语义通道是主力。
- **dense 单通道与 hybrid 接近**：本组查询不带结构化约束，属语义通道的主场；
  hybrid 的价值在带硬约束、带关键词的真实会话里更明显（见彩排）。
- **RAPTOR 消融是本轮最大发现**：岗位摘要节点把"标题+元数据+关键职责"压成一个
  聚焦向量，先命中岗位级摘要再展开到原文块，Top-5 精度 +13.3pp、MRR +0.145、
  NDCG@5 +0.160。这把 RAPTOR 从"预留接口"升级为"有数字支撑的可选增强"。

## 诚实声明（写论文必带）

1. 标签由 LLM 评审产生（`annotation_method=llm_judged_pooled`），未经人工复核；
   建议抽样 50–100 对做人工一致率估计后再写进正文。
2. 池化 Recall 是"池内召回"，池外可能存在未被任何通道召回的相关岗，Recall 绝对值
   偏乐观；本表的主要价值是**通道间相对比较**。
3. 演示语料的公司/城市为合成映射（JD 正文真实），评审判据已明确忽略实体名。
4. eval-015（niche 查询）池内仅 3 个相关岗——长尾查询的池化方差大，单 case 数字不稳。

## 如果分数不满意，按杠杆顺序改

1. **上 RAPTOR**（已建好，`include_raptor=True` 一开关的事）——本轮实测最大单项增益。
2. **Cross-encoder 精排 Top-20**（P2 预留）：对融合后前 20 做 (查询,JD) 拼接精排，
   预期再抬 NDCG；成本是每查询 20 次前向。
3. **查询构建**：把咨询产出的英文 title_keywords 并入 BM25 查询、中文目标翻译后扩展，
   拉高词面通道贡献。
4. **RRF 参数与通道权重**：k 值、bi-encoder 分数融合权重网格搜索（评估管线现成）。
5. **切块策略**：当前 max_chars=1800；对长 JD 试 800–1200 + 重叠窗口。
6. **换更强 embedding**（维度变更需重建索引与向量列，成本最高，最后考虑）。
