# Career-RAG 产品使用指南（群聊工作台 V2）

> 对齐实现：`eada18b`。本指南按用户在答辩演示中实际看到的顺序编写，不把内部日志、提示词或数据库状态包装成页面功能。

## 1. 产品是什么

Career-RAG 把一次职业匹配做成“职业规划服务群”。用户在同一条时间线上与四个角色协作：需求顾问·小意负责问清目标，岗位顾问·小检负责找岗位，规划师·小策负责差距与路径，项目经理·PM 负责监督和里程碑提示。

**证据可追溯** 的白话解释是：推荐理由能指回某一段 JD，简历建议能指回用户简历或澄清原话，而不是只显示一个无法核对的模型结论。

## 2. 页面与主流程总览

```text
登录/注册
  → 无会话空态三步引导
  → 新建咨询并上传简历
  → 简历档案手风琴 + 确认
  → 三个必需槽位 chips + 可选第四个澄清 chip
  → 咨询对话 / 简历澄清 / PM note
  → Match Brief：SQL 锁定栏 + 检索方向栏
  → 运行播报 + 服务进度卡
  → 分层岗位 / 证据 / 差距 / 简历建议 / 职业路径
  → 岗位反馈
```

桌面端由左侧会话栏和右侧工作台组成；移动端左栏收进导航抽屉。

## 3. 登录与额度

打开首页后看到“登录/注册”卡片。可用的邮箱、短信验证码通道由服务端能力接口决定，不会显示未配置的通道。首次验证成功会创建账号；后续使用同一身份登录。

登录会话使用 Cookie。若身份失效，前端统一回到登录入口。每个账号可创建的咨询会话数由 `SESSION_QUOTA_PER_USER` 配置；额度用完时，新建咨询会收到 402，界面显示额度说明弹窗。当前代码只有配额提示，没有真实支付流程。

答辩操作：先说明“认证是多人隔离的入口”，再登录；不要把开发环境的 console 验证码通道描述为生产短信或邮件服务。

## 4. 空态引导与新建咨询

登录后若还没有活动会话，右侧显示“职业顾问团队已就位”和三步说明：

1. 上传并确认简历；
2. 与顾问聊目标；
3. 查看带证据的岗位建议。

点击开始按钮创建会话。左侧会话栏可以切换历史咨询；新建咨询按钮会再次检查账号额度。

## 5. 上传简历（确认制）与档案手风琴

PM 欢迎气泡先介绍四个角色。上传走**两步确认制**（v3 B2）：

1. 点输入框左侧的 📎 选择文件（PDF/DOCX/TXT，视觉识别开启时也支持
   PNG/JPG/WEBP）→ 以你自己的气泡出现在群里，
   点「确认上传」发送。上传只做本地提取，**免费**；不支持的格式返回明确
   提示（不再静默硬吃），损坏文件也会立即告知。
2. 小意回一张预览卡：页数、字数、正文前 600 字、以及本会话解析额度
   （默认每会话 3 次）。点「**确认解析**」才开始调用 AI 整理档案——
   费用只在这一步发生。刷新页面或换设备回来，预览卡会自动恢复。

图片简历上传后不做视觉调用，免费预览固定显示“图片简历，确认解析后将进行
视觉识别（约几分钱）”。用户确认解析后才进行视觉识别，成本口径是约几
**分钱/次**，不是等待几分钟。PDF 会先保留本地逐页提取结果；文字少于阈值的
页面自动用视觉识别补读，单个 generation 最多补读 6 页。若 PDF 某页图像准备
或识别失败，该页原生文本仍保留，时间线会提示“视觉识别中断”“未识别”或
档案可能不完整，不会用空识别结果覆盖原文。

确认解析后时间线显示：

```text
正在归一化你的简历（解析 → 切证据片段 → 结构化 → 防编造校验）…
```

**归一化** 就是把不同排版的简历整理成统一的教育、经历、项目、技能结构。后台完成后，卡片显示教育段数、经历段数和技能项数，并提供”查看完整档案”手风琴。展开后可以核对：

- 教育、经历、项目与技能；
- 排版或内容质量问题；
- `R###` 原文证据片段。

需要换文件时随时用 📎 重新上传（不耗解析额度）。解析额度用完时，可在左侧
「开始新的咨询」新建会话继续；会话额度也用完时请联系管理员重置。

用户点击”确认简历档案”后才能开始咨询。确认不是永久锁死：重新上传会立即使旧确认失效，必须确认新版本。

## 6. 三项必需信息与“3+1”槽位 chips

输入框上方固定展示三个必需槽位 chip：

- 求职目标；
- 地点偏好；
- 签证情况。

空心圆表示尚未补齐，勾号表示完成；点击未完成 chip 会把对应提示放进输入框。进度条反映咨询信息完整度。用户还可以在“目标明确”和“探索方向”两种咨询模式间切换。

当简历澄清功能开启且存在含糊经历时，出现第四个 chip：

```text
简历补充：已回答 A，已跳过 S，待补充 R
```

这里的 A/S/R 来自后端状态，不是前端自行猜测。没有澄清目标、功能关闭或目标已耗尽时，只显示前三个必需 chip。

## 7. 咨询与简历澄清回路

### 7.1 用户会看到什么

小意先补齐三项必需信息。之后，如果归一化阶段发现某段经历过短、缺少职责/成果或带有高优先级质量问题，会针对一个具体目标提出一个问题。用户可以：

- 给出事实回答；
- 明确说跳过；
- 继续自然对话，系统按当前 pending 问题判断是否真正回答。

**pending 锚点** 的白话解释是：系统保存“上一轮到底问了哪一段经历、基于哪版简历问的”，下一轮只消费与这个问题对应的回答，避免把别的话误当成简历事实。

有效回答会成为 `C001`、`C002`……澄清证据，并保留用户原话。第四个 chip 随之更新已回答、已跳过和待补充数量；回答或跳过当前目标后，系统才移动到下一个目标。

### 7.2 用户应如何回答

推荐按“做了什么 + 用了什么 + 结果是什么”回答，例如：

```text
我用 Python 和 SQL 清洗销售记录，并把每周报表刷新流程缩短到原来的三分之二。
```

不要为了“提高匹配”补写不存在的经历。系统会保留这段原话作为可追溯证据，后续显式岗位检索、匹配解释或策略建议可以引用它。

### 7.3 隐私边界

澄清原话属于当前用户的简历证据。它不会直接拼进匿名案例空间的查询文本；隐式空间只使用脱敏后的结构化教育、经历、项目和技能。公开结果也只投影允许字段，不返回内部 pending、完整 SharedState 或模型提示词。

## 8. PM 咨询督导的可见行为

咨询期间，PM 可能插入一条独立气泡。出现时机有三类：

- 对话连续没有带来有效信息增量；
- 必需信息已齐，可以进入确认单；
- 刚进入更深入的职业讨论。

PM 不会每轮都说话。系统先用 L1 规则判断是否值得介入；**L1** 是“不调用模型、只看状态的检查”。满足触发与预算后才调用 L2；**L2** 是“让模型把已知事实组织成一条用户可读提示”。每轮至多一条，同类触发至多一次，总次数受 `CONSULT_COACH_MAX` 限制。

当 PM 判断条件已齐，它的气泡下方会出现“整理并确认匹配需求”操作。若 PM 模型超时或返回不可用内容，已发送的用户消息和小意回复仍然有效；页面不会因为一条督导提示失败而把整轮咨询判失败。这就是 **fail-open**：辅助功能失败时保住主流程。

PM note 只基于已持久化的咨询状态，不应被描述为新的用户事实或最终岗位结论。

## 9. Match Brief 确认单

用户结束咨询后，PM 展示 Match Brief。它是正式匹配前的“执行合同”，分成两栏：

| 硬条件（SQL 锁定） | 检索方向 / 排序参考 |
|---|---|
| 地点、签证、学历、经验等不可违反条件 | 目标岗位、软偏好、避开方向、结果数量等 |

点击确认后，后端锁定 `plan_version` 与 `plan_hash`，并为本次 run 快照 RAPTOR 和 Cross-Encoder 开关。用户批准的内容与实际执行计划一致；若简历版本已经变化，确认单不能沿用。

答辩时可以强调：左栏不是交给模型“酌情理解”，而是进入 SQL/metadata 过滤；右栏影响召回与排序，但不能让候选绕过左栏。

## 10. 运行播报与服务进度卡

确认单通过后，页面创建 run 并在 `plan_ready` 状态自动提交一次幂等执行。顶部服务进度卡持续轮询，时间线按阶段插入分隔线和角色播报，覆盖：需求整理、计划锁定、检索匹配、策略生成、终审核查、必要时的有界恢复、发布。

**幂等** 的白话解释是：同一个确认单重复触发不会产生两份互相冲突的结果。恢复播报出现时，表示 Supervisor 执行了受上限约束的重检索或修复，不表示存在无限循环。

运行时输入框会被禁用并提示在上方查看团队进展。页面刷新后会从本地保存的 run id 重新读取持久化状态；这不等于服务重启会自动重新调度所有未完成 run。

## 11. 结果区与反馈

完成后，PM 气泡内显示结果卡：

- **Now Fit**：当前证据下较直接匹配；
- **Stretch Fit**：存在差距但值得尝试；
- **Bridge Role**：用于补齐能力或过渡的岗位；
- 每个岗位的匹配说明、JD evidence 和可用的简历 evidence；
- 技能差距、简历修改计划和职业路径；
- 查看证据、查看评估解释、新建或细化咨询等操作。

点击证据会打开抽屉；关闭后焦点返回原触发按钮。岗位反馈表可以提交结果和评分，写入反馈闭环。结果是职业决策辅助，不是录用承诺，也不应把离线排名指标说成个人成功概率。

## 12. 409 生命周期恢复状态

**409** 表示”请求本身格式没错，但它依据的简历/对话版本已经不是当前版本”。发生生命周期冲突时，前端清空过期确认单，并同时重新获取简历预览和咨询状态。用户会看到以下固定文案：

| 状态 | 页面文案 | 用户动作 |
|---|---|---|
| 新上传正在归一化 | **新简历处理中** | 等待自动轮询；不要重复发送当前咨询轮次。 |
| 当前 generation 归一化失败 | **这份文件我没能整理成功，旧档案已作废** | 用输入框左侧 📎 重新上传可解析文件（预 AI 阶段失败不扣解析额度）。 |
| 解析额度用尽 | **本会话解析次数已用完（3/3）** | 新建会话继续；会话额度也满时联系管理员重置。 |
| 新预览已经 ready | **简历已更新，本轮未提交；请确认新档案后重试** | 展开核对新档案，确认后再发送。 |

这三态不是“随便重试”的错误提示：它们分别对应 processing、error、updated，目的是防止用户在旧档案上继续咨询。

## 13. 移动端抽屉

窄屏下，历史会话、个人资料、评估、监控和退出入口收进导航抽屉。打开后焦点进入抽屉，Tab 不会跳到背景；按 Escape、点击遮罩或选择导航项会关闭，焦点回到打开按钮。群聊、上传、发送和结果证据在移动视口仍走同一业务流程，不存在独立的“简化版后端”。

## 14. 答辩演示建议顺序

1. 登录，指出认证与每账号会话隔离。
2. 展示空态三步，再进入已经准备好的会话。
3. 上传简历，展开档案与 `R###` 证据，确认版本。
4. 用 chips 补齐三项必需信息；回答一个澄清问题，展示 `3+1` 进度。
5. 展示一条 PM note，并说明 L1/L2、预算与 fail-open。
6. 打开 Match Brief，对比“SQL 锁定”和“检索方向”两栏。
7. 确认并观察进度卡、阶段播报与结果三分层。
8. 打开 JD/简历证据抽屉，再提交一条岗位反馈。
9. 若演示 409，使用预置竞态场景并按三态文案解释，不在现场制造不可控网络故障。
