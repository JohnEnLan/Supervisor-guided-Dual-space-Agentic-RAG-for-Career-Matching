# 产品文档 —— 这个系统作为"产品"到底是什么

> 配套阅读：`docs/code_guide.md`（代码怎么实现的）。本文只讲产品：给谁用、解决什么、每个页面干什么、凭什么可信。

---

## 1. 一句话定位

**面向学生和初入职场者的"证据驱动"职业匹配服务**：不只告诉你"哪些岗位适合你"，还告诉你"为什么、差在哪、下一步怎么办"。岗位推荐可以点开看 JD 原文证据；简历建议等策略项在系统内部经过证据 ID 硬校验（拿不出出处会被删掉），前端对这部分出处的完整展示仍在完善中。

## 2. 解决什么问题（普通求职工具的三个痛点）

| 痛点 | 普通工具 | 本产品 |
|---|---|---|
| 搜索只看关键词 | "Python"搜不到写着"熟悉脚本开发"的岗位 | 关键词 + 语义双路检索，融合排序 |
| 推荐是黑箱 | "为你推荐"但说不出为什么 | 每个发布的推荐附 JD 原文证据（简历事实映射接口已预留） |
| 只给岗位不给路 | 匹配完就结束 | 三档分层 + 技能缺口 + 简历修改 + 短中长期路径 |

再加两条别家很少做到的底线：**硬条件绝不妥协**（需要签证就是需要，AI 没资格放宽），**无证据建议不发布**（简历建议必须携带指向你真实简历片段的有效证据 ID 才能发布，另有防编造核查兜底；系统校验的是引用有效性，不做语义级真伪判断）。

## 3. 用户旅程（7 步）

```
① 创建会话，上传简历（PDF/DOCX/TXT，文件选择方式）
② 查看归一化档案并确认——页面下方可展开全部原文证据片段对照（暂未做到每条经历旁内联显示）
③ 和需求顾问对话：目标明确选 Targeted，迷茫选 Explore；最多被追问一次
④ 签 Match Brief 确认单（内容不可变）：硬条件全程冻结；软偏好在"结果过少"的有界恢复中可被临时放宽一次并留日志
⑤ 提交运行，两种视角围观：
     · 进度板：七阶段进度条
     · 服务群：四位"同事"群聊直播（需求顾问复述你的要求→岗位顾问播报检索→
       规划师播报建议→PM 播报最终核查与返工/修复事件）
⑥ 查看结果：
     · Now Fit（现在就投）/ Stretch Fit（值得冲）/ Bridge Role（跳板岗）
     · 每岗位：为什么推荐 + JD 原文证据（"对应简历哪条事实"接口已预留，当前不保证每岗都有）
     · 技能缺口清单、简历逐条修改建议、短中长期路径
⑦ 反馈：有帮助 / 不相关 / 已投递 / 获得面试 + 1–5 分评价（写入私有反馈记录；自动沉淀为匿名案例的闭环属后续工作）
```

## 4. 页面清单

| 页面 | 给用户的价值 |
|---|---|
| 落地页 | 产品叙事开场（职业远征主题） |
| Workspace | 建会话 + 上传简历 |
| 简历确认页 | 结构化档案 + 可展开的原文证据列表 + 质量提醒，确认后才继续 |
| Brief 页 | 咨询对话 + 确认单表单（地点/签证/偏好/排除岗位/结果数） |
| 运行页 | 七阶段进度，可随时刷新恢复，可切群聊视角 |
| **服务群页** | 本产品的差异化体验：把 AI 流水线拟人成 4 人服务团队，过程透明可讲 |
| 结果页 | 三档岗位卡片 + 证据抽屉 + 建议与路径 + 反馈入口 |
| 评估页（开关控制） | 每个岗位排名怎么来的（显性排名/隐性排名/隐性权重/案例证据）、阶段耗时、返工记录 |
| 监控页（开关控制） | 完成率、失败率、P50/P95 耗时、证据覆盖率、隐性空间使用率 |

## 5. 三个信任设计（答辩时的产品卖点）

1. **证据可溯源**：推荐理由带 JD 出处，前端点开即原文；简历建议在系统内部带出处编号并有硬性校验——拿不出出处的建议会被系统证据门过滤（第一道在策略生成时的确定性过滤，PM 终审再复核一遍；这部分出处的前端展示仍在完善）。
2. **硬条件确定性**：签证、地点、经验、学历走数据库 WHERE 条件；AI 的"我觉得这个也行"只能作为参考意见，没有否决权和放行权。
3. **过程透明有界**：关键阶段与每次返工事件对用户可见（群聊播报 + 评估页的恢复事件）；PM 的完整逐项检查日志保存在内部状态，供审计与答辩取证。返工每类最多一次，不存在"AI 自嗨转圈圈"。

## 6. 数据与隐私

- 简历原文和反馈按用户/会话隔离存储，公开接口只吐"投影后"的结果，内部状态永不出境；
- 匿名案例库只存去标识化的背景模式（有 PII 检测拦截邮箱/电话/链接）；
- 执行过程的断点快照（含简历内容）在任务结束后立即删除，另有每小时的兜底清理。

## 7. 双空间（P1 机制，演示级）

- **显性空间**＝真实岗位库：负责"现在有哪些岗位适合你"；
- **隐性空间**＝匿名案例库：负责"历史上和你相似的人，投这类岗位走到了哪一步"，只在显性结果内做小幅重排（影响力有上限、可关闭）；
- 产品承诺：隐性空间永远不会创造岗位、永远不会绕过你的硬条件。

## 8. 当前边界（诚实清单）

- 仓库附带 LinkedIn 样本数据文件（50/1000 条两档；实际库内数量取决于部署时导入哪档），3 万条扩容有设计方案未实施；
- 反馈→案例的自动沉淀闭环未接到新版接口（手动种子数据可演示）；
- 单机部署：任务执行在进程内。断点续跑是"能力"而非"自动行为"——checkpoint 支持再次触发同一 run 时从断点继续，但服务重启不会自动重调度中断的 run（超过阈值后由启动/周期扫描标记为 stale）；
- 前端证据展示未覆盖全部策略项（简历建议/技能缺口/路径的出处编号在接口里、未全部渲染），简历确认页原文对照为整页列表而非逐条内联；
- 账号体系未实现（当前以 user_id 直传，注册登录方案见 `docs/auth_technical_design.md`）。

## 9. 指标怎么读（给答辩）

- **找得准不准**：Precision@K / Recall@K / MRR@K / NDCG@K（检索质量）
- **说得真不真**：JD 证据覆盖率、岗位级引用有效率（结构性忠实度：解释非空且引用的证据 ID 确属该岗位；不判断语义层面是否支持）
- **跑得稳不稳**：完成率、警告率、阶段耗时 P50/P95、恢复事件数
- **有没有用**：用户反馈（有帮助/不相关/已投递/获得面试 + 评分）
四层指标闭环对应产品四个承诺：准、真、稳、有用。
